# Call Team IVR Hotline Dashboard

A professional, pink-themed dashboard that turns the **Call Team IVR Google Sheet** into a
visual, easy-to-follow IVR flow chart for every hotline/brand.

**To add or update a hotline, update the corresponding Google Sheet tab. The website
automatically detects the updated data during the next synchronization (every 15 minutes).**

---

## 1. Project purpose

Call-team agents and team leads need to quickly see the IVR flow for each hotline. This
dashboard reads the Google Sheet (the single source of truth), converts each tab into a
brand/hotline page, and renders the IVR as a visual flow diagram — greeting, menu options,
submenus, transfers, agent queues, email endpoints, repeat-message and no-agent fallbacks.

## 2. Tech stack

- **Frontend:** vanilla HTML / CSS / JavaScript (no framework, no build step for the site)
- **Data pipeline:** Node.js + [SheetJS (xlsx)](https://sheetjs.com/) — runs in GitHub Actions
- **Hosting:** GitHub Pages (static)
- **Automation:** GitHub Actions — fetches the sheet, parses it, deploys every 15 minutes
- **Domain:** `ivr.daniellecrizaldo.com`

## 4. Google Sheet setup

The sheet is the **single source of truth**. Requirements:

- **One tab per brand/hotline.** The tab name becomes the brand name.
- Each tab is laid out as a **flow diagram**: text cards (optionally merged cells) connected
  by downward arrows (`⬇️`). The parser reads the card positions and arrow connections to
  rebuild the flow.
- The sheet must be **link-shared** ("Anyone with the link → Viewer") so the build can read it
  without credentials. If you restrict it, see §6 for the service-account option.

Current sheet: `Call IVR FLOW` (ID `1HZtIq4jt4EHrw2Ord3yqXkdLOHN7h-EDJYK7SbyeQKY`).

## 5. Google API setup

The default build uses the **public xlsx export endpoint** — no Google API key or OAuth is
needed because the sheet is link-shared. Nothing sensitive is exposed to the browser.

## 6. Required GitHub Secrets

Configure these in **Settings → Secrets and variables → Actions**:

| Secret | Required? | Purpose |
|--------|-----------|---------|
| `GOOGLE_SHEETS_ID` | Yes | The spreadsheet ID. The build falls back to the default if unset. |
| `GOOGLE_SERVICE_ACCOUNT_JSON` | Only if the sheet is private | A service-account JSON to authenticate the read. |

> ⚠️ **Never commit real credentials.** Only placeholders live in `.env.example`.
> No Google credentials, API keys, or tokens are ever written into HTML, JS, CSS, JSON,
> localStorage, or the repository.

The site is fully static — it reads `data.json` and renders client-side, so you can test

## 8. Production deployment

Pushing to `main` triggers the workflow. It also runs **every 15 minutes** and on manual
dispatch (Actions → "Sync IVR data & deploy" → Run workflow). The workflow:

1. Fetches the Google Sheet **server-side** (no credentials in the browser).
2. Parses every tab into `public/data.json`.
3. Deploys the `public/` folder to GitHub Pages.

The site is served at **https://ivr.daniellecrizaldo.com** (CNAME → GitHub Pages).

## 9. How the 15-minute refresh works

- **Server side:** GitHub Actions runs the build every 15 minutes, regenerating `data.json`
  from the live sheet and redeploying.
- **Client side:** the dashboard re-fetches `data.json` every 15 minutes (and when the tab
  regains focus) without reloading the page. A **Refresh** button in the top bar forces an
  immediate sync. The **Last Updated** timestamp shows when the data was generated.
- If a fetch fails, the dashboard keeps showing the **last successfully-synced data** (cached
  in the browser) and tells you so.

## 10. How to add a new brand

1. In the Google Sheet, add a new tab named after the brand (e.g. `Acme Hearing`).
2. Lay out its IVR flow: text cards connected by `⬇️` arrows.
3. Within 15 minutes the dashboard picks it up automatically — a new card appears on the home
   page and a new `/brand` page is generated. **No code changes needed.**

## 11. How to modify IVR information

Edit the text in the relevant tab. The next sync (≤15 min) reflects the change. To see it
immediately, click **Refresh** in the top bar.

## 12. Troubleshooting

| Symptom | Cause / fix |
|---------|-------------|
| "Couldn't reach the data source" | Sheet not link-shared, or network issue. Make the sheet public (Viewer) or add `GOOGLE_SERVICE_ACCOUNT_JSON`. |
| A brand is missing | Its tab is empty or has no cards. Add content to the tab. |
| A branch looks wrong | The tab's arrows/cards aren't connected as expected. Check the card layout in the sheet. |
| Stale data after an edit | Wait for the 15-min sync, or click **Refresh**. Hard-refresh the browser (Ctrl+F5) to bypass cache. |
| Blank cells | Blank cells are skipped safely — they don't break the chart. |

## 13. Security considerations

- **No credentials in the browser.** The sheet is read server-side in GitHub Actions; the
  browser only ever loads the generated `data.json`.
- **No secrets in the repo.** `.env.example` holds placeholders only. Real values live in
  GitHub Secrets.
- **No personal access tokens committed.** If a token is ever found in tracked files, remove
  it and rotate it immediately.
- The deployed site is public (GitHub Pages). Do not put private customer data in the sheet
  unless that's intended.
